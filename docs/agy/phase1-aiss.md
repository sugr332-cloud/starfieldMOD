## 作業1': 日本語で返事させる・表示を通常にする（最優先。止まらずに進めてよい）

1. **日本語にならない原因**
   - LM Studio のサーバーログで、このとき AISS から送られたプロンプトに、日本語アドオン（jp_prompt_pack の system_preface_append.txt）の内容が含まれているかを確認する
   - 含まれていなければ、アドオンが読み込まれていない原因（Backend をランチャーから直接起動したことで MO2 の別MOD「AISS - Japanese Language Addon」のフォルダが見えていない等）を特定して直す。Backend が直接起動の場合にアドオンを読むフォルダ（AISS 本体側の addons か、設定でアドオンの場所を指定できるか）を AISS 付属ドキュメントで確認する
   - 含まれているのに英語なら、指示が弱い・後ろの英語の指示に負けている可能性がある。AISS の設定に「応答言語」の項目があればそれを日本語にする。なければ、日本語指示の置き場所（system_preface / conversation_rules）と書き方を強める
   - ト書き（`*...*`）は、Phase 1.5 の読み上げで邪魔になる。AISS の設定でト書きを出さない、または日本語で短くする方法があれば記録する（今は変更しなくてよい）
2. **「DEBUG」ボックスで表示される原因**
   - AISS の config.json や設定で、デバッグ表示（返事をメッセージボックスで出す）が有効になっていないか確認する。通常の表示（会話・字幕）に戻す設定があれば戻す
   - 付属ドキュメントで、返事の通常の表示方法（字幕・会話メニュー・HUD 等）を確認し、報告に書く
3. 返事が届くまでの時間を、ログの時刻から計算して記録する（送信 → 返事）

## 作業1: どこで止まっているかの特定（参考。作業1'の確認に必要な範囲で行う）

送信から返事までの各段階について、15:20〜15:30 頃の記録を時刻付きで確認し、どこまで進んだかを表にする。

| 段階 | 確認するもの |
|---|---|
| 1. ランチャーが Backend を起動したか | ランチャーのログ、AISS_Backend.exe のプロセスが現在も動いているか |
| 2. ゲームがリクエストを書いたか | requests/latest_request.ini の内容（message=hi、ready 等）と更新時刻 |
| 3. Backend がリクエストを読んだか | Backend のログ（aiss_rebuilt_backend.log 等）、runtime_health.json |
| 4. Backend が LM Studio に送ったか | Backend のログ、LM Studio のサーバーログ |
| 5. LM Studio が返事を生成したか | LM Studio のサーバーログ（生成時間・エラー） |
| 6. Backend が返事を書いたか | responses/latest_response.ini の内容と更新時刻 |
| 7. ゲームが返事を読んだか | state/hud.ini、SFSE / AISS のログ |

- Backend が、ランチャーから直接起動されたことで、MO2 経由のときと違うフォルダを監視していないか確認する（requests を読むパス・responses を書くパスがゲーム側と一致しているか）
- Backend が直接起動されたときにコンソールウィンドウが表示されるか、すぐに終了していないかを確認する
- 原因が特定できたら修正する。ゲームでの確認が必要ならユーザーへの手順を報告に書く

### 作業4: 25秒の内訳の特定

LM Studio のサーバーログから、直近の数回の会話それぞれについて以下を表にする。
- 入力トークン数（AISS が送ったプロンプトの長さ）
- プロンプト処理（prefill）にかかった時間と、プロンプトキャッシュが効いたか（再利用されたトークン数）
- 思考（reasoning）トークンが出ていないか
- 出力トークン数と生成時間（tokens/s）
- Backend 側の待ち時間（ログの時刻差）

### 作業5: 速くするための設定（効果の大きい順に試し、各段階の秒数を記録）

1. **返事を短くする**: 日本語アドオンが効くようにし（作業1'）、「1〜3文」の指示を守らせる。AISS に最大出力トークン数の設定があれば 150 前後に制限する
2. **送る文脈を減らす**: AISS の設定で、1回に送る文脈（記憶・ワールド情報・会話履歴・周囲の状況など）の量を減らせる項目を探す。会話の質を大きく落とさない範囲で、入力トークン数を半分程度（約6,000）に減らす案を出す
3. **プロンプトキャッシュを効かせる**: AISS のプロンプトの先頭部分が毎回変わってキャッシュが効いていないなら、その原因（時刻・位置など毎回変わる情報が先頭にある等）を記録する。AISS 側の設定で順序を変えられるなら変える
4. **ゲーム中の GPU の取り合いを減らす**: ゲームのフレームレート上限（例: 60fps）を設定すると LLM の処理が速くなるかを、設定方法とともに報告する（ゲームでの計測はユーザーが行う）
5. 上記で足りない場合の選択肢を、見込み秒数とともに報告する（実行はしない）
   - LLM をリビング PC（RX 7600 8GB）で動かす: ゲームと GPU を取り合わない代わりに、12B が 8GB に収まるか・速度
   - モデルの変更（ユーザーは会話の質を落としたくない方針。参考情報として）

### 目標

- 送信から返事の表示まで **10秒以内**（できれば 5〜8秒）
- 報告には、設定変更前後の秒数と、ユーザーが体感を確認する手順を書く

### 修正1: 思考はプロンプトではなく設定で確実に止める（重要）

- 思考の有無はプロンプトの指示では確実に制御できない。さらに `max_tokens: 150` の状態で思考が出ると、**150 トークンを思考で使い切り、返事が空・途中で切れる**おそれがある
- AISS 経由のリクエストで思考が出ない設定を、以下の順で確認して適用する
  1. LM Studio の gemma-4-12b-it-qat のモデル設定（推論・思考のオン/オフ、チャットテンプレートの思考フラグ）で思考をオフにする。モデル別の既定設定として保存し、プリセットに依存しないようにする
  2. AISS の config.json に、LM Studio へ送るリクエストのパラメータ（reasoning_effort、chat_template_kwargs 等）を指定できる項目があれば、思考オフを指定する
- 適用後、LM Studio に AISS と同じ形式のリクエスト（約8,000トークン）を送り、**思考トークンが 0** であることをサーバーログで確認する
- 思考が 0 になったことを確認できたら、`max_tokens` は 150 ではなく **250** 程度に戻す（日本語は英語よりトークン数が多く、150 だと 2〜3文の途中で切れることがあるため）

### 修正2: 返事の表示方法

- HUD 通知（画面右上）は表示時間が短く、長い文が切れたり読み終わる前に消えたりすることがある。AISS 付属ドキュメントで、返事を字幕・会話メニュー・その他の方法で表示する設定があるか確認し、選択肢を報告する（今は HUD 通知のままでよい）
