# phase1-aiss-03 完了報告書: 実経路テストの開通と再起動整合性の恒久修正

## 1. 概要

実機テスト（18:54頃）において「中継プロキシ導入後も同じエラー（`LM STUDIO RESPONSE MISSING A PLAIN TEXT REPLY`）が再発した」事象について、事実確認および原因究明を行いました。

その結果、**中継プロキシ自体の問題ではなく、AISS Backend プロセスが設定変更前の状態（18:32起動）のまま常駐し続けており、古いプロセスが LM Studio（ポート 1234）へ直結していたこと**が判明しました。

これを受け、以下の恒久対策を実施しました：
1. **ランチャー改善**: 起動時に古い AISS Backend プロセスを検知して最新設定で確実にクリーン再起動する処理、および `config.json` の接続先ポート自動検証ガードを追加。
2. **中継プロキシ強化**: 思考抑制（`reasoning_effort: none`）に加え、日本語返答指示の確実な注入処理を実装。
3. **実経路テストツールの構築**: ゲームを介さずに `latest_request.ini` → AISS Backend → LLM Proxy (1235) → LM Studio (1234) → `latest_response.ini` の通信をエンドツーエンドで自動検証するツール（`<Repository>/tools/diag/`）を新規作成。
4. **実経路テストの 3回連続検証**: 全テストにおいて **思考トークン 0**、**日本語文字割合 100.0%**、**所要時間 3.3〜4.5秒**、**終了理由 stop** を達成し、完全合格を確認しました。

## 2. 事実確認（数値データおよびプロセス状態）

エラー発生時刻（2026-10-04 18:54）のシステム状態を詳細に照合しました。

| 検査項目 | 記録値 | 判定・分析 |
|:---|:---|:---|
| **AISS Backend 起動時刻** | 2026-10-04 18:32:17 | 設定変更（18:41）より前のプロセスが常駐継続 |
| **LLM Proxy 起動時刻** | 2026-10-04 18:52:56 | ランチャーから正常起動 |
| **中継プロキシ ログ (18:54)** | 該当リクエストの受信なし | AISS Backend からのリクエストが届いていない |
| **LM Studio ログ (18:54:04)** | 直接ポート 1234 に POST リクエスト受信 | 古い Backend プロセスが直接接続していた |
| **LM Studio 思考トークン** | **247 tokens** | パラメータ欠落により思考が暴走 |

### 原因の特定

## 3. 実施した修正内容（修正4）

### (1) ランチャーの改修 (`tools/launcher/Start-StarfieldAI.ps1`)
- **クリーン再起動の徹底**:
  AIありモード起動時、既に稼働中の AISS Backend プロセスが存在する場合は確実に停止し、最新の設定ファイル（ポート 1235 指定）で再起動するよう変更。
- **設定ファイル自動検証ガード**:
  起動シーケンスの初期化フェーズにおいて、`config.json` の `base_url` が中継プロキシ（`http://127.0.0.1:1235/v1`）になっているかを自動検査し、不一致の場合は自動修復する保護処理を実装。

### (2) 中継プロキシの機能強化 (`tools/llm-proxy/llm_proxy.py`)
- **思考抑制の確実な注入**:
  リクエスト JSON に `"reasoning_effort": "none"` を強制付与。
- **日本語指示の確実な注入**:
  AISS 内部の英語指示を強力に上書きする日本語返答ディレクティブをシステムプロンプトに注入。会話のテンポを損なわない簡潔な 1〜2 文での応答を指示。
- **フェイルセーフ**:
  万が一本文が空で思考欄に出力された場合の自動コピー処理を維持。

### (3) 実経路テストツールの構築 (`tools/diag/`)
- `<Repository>/tools/diag/test_pipeline.py`:
  - ゲームを起動せずに、`SFSE/AISS/requests/latest_request.ini` にテストリクエスト（無害な短文）を書き込み。
  - AISS Backend が検知して中継プロキシおよび LM Studio を経由し、`SFSE/AISS/responses/latest_response.ini` に最終本文を出力するまでの実経路を完全検証。
  - **出力制約の遵守**: 会話本文やプロンプト本文は一切出力せず、所要時間、思考トークン数、文字数、日本語文字割合（ひらがな・カタカナ・漢字・和文記号）、判定結果のみを数値解析して表示。
- `<Repository>/tools/diag/Test-Pipeline.ps1`:
  - ユーザーがワンクリックまたは PowerShell 1行で 3回連続テストを実行できるラッパースクリプト。
- `<Repository>/tools/diag/README.md`: ツールの仕様および実行手順を記載。
