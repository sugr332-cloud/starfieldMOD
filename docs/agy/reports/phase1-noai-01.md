# phase1-noai-01 完了報告書: AI会話（AISS）の取りやめと環境一本化

## 1. 概要

ユーザーの明示的な決定に基づき、AI 会話（AISS + LM Studio）を取りやめ、以後は **AI なしの MOD 構成（`Stable-NoAI`）** だけで快適に遊べるようシステムおよびドキュメントの一本化を実施しました。
また、`phase1-aiss` の修正7は直ちに中止しました。

MOD やツールのファイル群は**削除せず保持**しており、将来的に再開したくなった場合には即座に復元可能です。

---

## 2. 作業1: 起動アイコンの整理および LM Studio の完全オフ（VRAM 解放）

### (1) デスクトップショートカットの整理
- **`Starfield（MOD）.lnk` への改名**:
  既存の「Starfield（AIなし）」アイコンを **「Starfield（MOD）」** に改名しました。
  ダブルクリックすることで、`tools/launcher/Start-StarfieldAI.bat -NoAI` が呼び出され、LM Studio や AISS Backend を一切起動せず、MO2 の `Stable-NoAI` プロファイルで SFSE を直接起動します。
- **不要アイコンの削除**:
  デスクトップ上にあった「Starfield（AIあり）」および「AISS 状態確認」のショートカットを削除しました（※ランチャー本体や診断ツールのスクリプトファイル自体はリポジトリ内に保持されています）。

### (2) LM Studio および関連プロセスの完全オフ（VRAM 解放）
ユーザーの「VRAM を使いすぎるため完全にオフにする」という要望に基づき、以下の停止処理を実施しました：
1. **モデルのアンロード**: `lms unload --all` を実行し、VRAM を約 6.9 GB 占有していた `gemma-4-12b-it-qat` を完全解放。
2. **ローカルサーバー停止**: `lms server stop` を実行し、ポート 1234 のリスナーを停止。
3. **プロセスの完全終了**: LM Studio アプリ本体、バックグラウンドの `llama-server`、中継プロキシ（`llm_proxy`）、AISS Backend プロセスをすべて終了。
4. **自動起動・常駐設定の確認**: Windows ログイン時の自動起動やタスクスケジューラ、バックグラウンドサービスへの登録がないことを確認。

#### GPU 専用メモリ（VRAM）使用量の測定結果
- **LM Studio 停止前**: **15,374,090,240 bytes (約 14.32 GB / 14.67 GiB)**
- **LM Studio 停止後**: **10,200,887,296 bytes (約 9.50 GB / 9.73 GiB)**
- **VRAM 解放量**: **約 4.82 GB (5,173,202,944 bytes) 解放！**

VRAM の空き容量が大幅に増加し、Starfield が高画質・高フレームレートで安定稼働するための十分なメモリ余力が確保されました。
