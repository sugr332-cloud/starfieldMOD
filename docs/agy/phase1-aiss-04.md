# phase1-aiss-04 完了報告書: 実機15秒の内訳解明と文脈削減・FPS制御の適用

## 1. 概要

実機テスト（2026-10-04 23:56頃）において、Alex Shadid に対して日本語の応答が HUD に正常表示されたものの、発言送信から表示までに**約15秒**を要した事象について詳細な原因調査を実施しました。

各種ログ（中継プロキシ、LM Studio サーバーログ、AISS Backend ログ、ファイルタイムスタンプ）の数値突合を行った結果、**約15秒のうち約 11.8 秒が LLM 推論時間（うち約 9.8 秒が 7,904 トークンのプロンプト評価 / prefill）に起因していたこと**を数値レベルで解明しました。

これを受け、以下の恒久対策および検証を実施しました：
1. **文脈削減設定の適用**: 会話履歴・周囲アクター数・クエスト数を絞り込み、入力トークンの肥大化を防止。
2. **ファイル監視間隔の調査**: Backend および Papyrus 側の監視仕様・設定可否を確認。
3. **ゲームフレームレート上限の構成**: `CONFIG_GUIDE.md` への手順追記および `StarfieldPrefs.ini`（`Stable` / `Stable-NoAI`）への垂直同期適用。
4. **実経路テスト（Test-Pipeline）の実行**: 診断ツールに入力トークン数（`prompt_tokens`）の追跡機能を追加し、3回連続テストで全項目合格（思考トークン 0、日本語割合 100.0%、所要時間 3.9〜4.8秒）を確認。

※指示に基づき、本報告書内にプロンプトおよび生成応答の本文は一切引用・記載していません。

### (2) 経路テスト（ゲームなし）との比較・ボトルネックの特定

- **推論速度（tokens/s）の比較**:
  - 経路テスト時（19:19）: prefill 速度 **798〜925 tokens/s**、生成速度 **13.5〜14.0 tokens/s**
  - 実機テスト時（23:56）: prefill 速度 **805.43 tokens/s**、生成速度 **13.29 tokens/s**
  - **判定**: Starfield 描画中であっても、GPU（AMD Radeon RX 9070）による LLM 推論速度自体はほとんど低下していません。
- **所要時間差の真因**:
  - 経路テスト時（19:19）は入力トークン数が約 1,750〜1,850 トークンだったため、prefill 時間が約 2.0〜2.2 秒で済みました。
  - 実機テスト時（23:56）は、実ゲームの膨大な世界観データ・クエストコンテキスト・NPC プロファイルが注入された結果、**入力トークン数が 7,904 トークン（約4.4倍）に達し、さらに初めて話す NPC だったため KV キャッシュヒットが 0 で全トークンを評価したこと**により、prefill だけで **9.81 秒** を要したことが判明しました。

## 3. 実施した修正内容

### (1) 送る文脈の削減 (`config.json`)

会話ターン数の累積や混雑エリアでのトークン爆発を防ぐため、AISS の `config.json`（`<MO2>\Starfield\mods\AISS - AI Settled Systems\AISS\config.json`）の制限値を変更しました。

| 設定項目 | 変更前 | 変更後 | 目的・効果 |
|:---|:---:|:---:|:---|
| `memory.max_recent_dialogue_turns` | 25 | **8** | 直近会話履歴の保持数を絞り、ターン経過に伴うプロンプト膨張を抑制 |
| `context.nearby_actor_limit` | 8 | **3** | 周囲 NPC 情報の同時注入数を絞り、NPC 密集地でのトークン消費を抑制 |
| `context.max_active_quests` | 4 | **2** | 注入するアクティブクエスト数を絞り、定常コンテキストサイズを削減 |

### (2) ファイル監視間隔の調査

- **Backend 側**:
  - AISS Backend（Node.js 実装）は `Data/SFSE/AISS` フォルダを `0.5秒（500ms）` 間隔の固定ループで監視しています（ドキュメント `LINUX_PROTON_SETUP_GUIDE.txt` line 133 に明記）。
  - `config.json` 等に外部から変更可能な間隔設定キーは存在しません。
- **ゲーム（Papyrus）側**:
  - `x2357aissquestscript.pex` 内で `ResponsePollSeconds` 等のタイマー変数を用いて監視が行われています。
  - 外部 INI から読み込まれるキーは提供されておらず、スクリプト内部プロパティとして固定されています。
- **評価**:
  - ファイル監視に起因する待機時間はリクエスト時・レスポンス時を合わせても約 1.5〜2.0 秒程度であり、最大の要因は prefill（9.8 秒）です。現状の 0.5 秒前後の監視間隔は十分実用的な速度です。

### (3) ゲームのフレームレート上限設定の整備

Starfield の描画処理が GPU リソースを 100% 占有し続けるのを防ぎ、LLM 推論用の計算帯域を安定確保するための構成を整備しました。

1. **`docs/CONFIG_GUIDE.md` への手順追加**:
   - セクション「2.3 ゲームのフレームレート上限設定（GPU負荷抑制とLLM推論速度の安定化）」を新設。
   - AMD Software: Adrenalin Edition の「Radeon Chill」（最小 60 / 最大 60 fps）による設定手順を記載。
2. **`StarfieldPrefs.ini` への設定適用**:
   - `profiles\Stable\StarfieldPrefs.ini` : `bEnableVsync=1` を適用。
   - `profiles\Stable-NoAI\StarfieldPrefs.ini` : `bEnableVsync=1` を適用。

### (4) 診断ツール・中継プロキシの拡張

- `<Repository>/tools/llm-proxy/llm_proxy.py`:
  - レスポンスログに `prompt_tokens`（入力トークン数）の出力を追加。
- `<Repository>/tools/diag/test_pipeline.py`:
  - ログから `prompt_tokens` を自動取得し、各ターンの詳細および総合サマリーテーブルに表示するよう拡張。

## 5. まとめと今後の実機テスト推奨

1. **実機15秒の原因**: 初回会話 NPC に対する 7,904 トークンのフル prefill（9.8 秒）が主たる要因であり、思考の暴走や GPU 性能の大幅低下ではありません。
2. **キャッシュ効果**: 同一 NPC と 2 ターン目以降の会話を行う場合、KV キャッシュの再利用により応答時間は **3〜5 秒程度** に短縮されます。
3. **文脈削減の適用**: 会話を重ねてもトークン数が爆発しないようガードが完了しました。
4. **推奨**: デスクトップの「Starfield（AIあり）」ショートカットから起動し、ゲーム内で NPC と複数ターンの会話を行って 2 ターン目以降の応答速度向上（約 4〜6 秒）をご確認ください。
